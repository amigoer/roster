# 总体设计

> 第一轮 · 2026-09-12 · 最近改动 2026-09-18（会话里另选权限档）

## 定位

传统 code agent + bot。参照物是 Claude Desktop 加一层 bot 形态。

**桌面 app 是本体，手机是它的远端。** agent 程序、仓库、密钥、登录都在桌面机上；手机不跑任何东西，只负责在离开桌面的时候看得到、答得上（见 [移动端](mobile.md)）。本体开源免费，直连和自建中继也免费、也完整；付费订阅买的是官方中继和推送。

## 形态：现代 IM

左边导航栏和会话列表，右边详情（见「三列布局」）。两种会话：

- **session** —— 单个 agent，默认形态，就是普通的一对一聊天
- **bot team** —— 多个 bot，群聊形式，消息带发送者身份

选 IM 是因为 agent 会话本来就是消息流，而「多条会话并存 + 未读提醒 + 快速切换」这套交互已经被 IM 验证过，不需要重新发明。

## bot = 联系人

预设 bot 就是 IM 里的联系人。**bot 是持久、可复用的定义**（名字、头像、系统提示、工具集、模型、权限档），会话只是它的一次实例化 —— 同一个 bot 可以同时出现在任意多个会话里。

于是「新建会话」不用发明新交互：挑一个联系人开 session，挑多个开 bot team，群里还能中途拉人、踢人。

左侧导航栏因此有两个入口：**消息**、**通讯录**。

## 群 = agent team

拉群就是组 team。**群本身是持久对象** —— 有名字、成员、历史，下次回到同一个群接着干。

**会话是工作单元**：bot 在通讯录里是全局的、不绑任何代码；要干活时拉一个群，这个群持有 worktree、历史、成员。**一个 bot 也是群**（双人群）：单聊是纯聊天，不绑仓库。底层两者是同一个对象，session 就是只有一个成员的群。

**repo 绑在会话上，不引入「项目」层。** 建群时选工作目录，之后这个群就在那儿干活。会话列表因此是扁平的 —— 跟 IM 一样，不同群聊混在一个列表里，卡片上标 repo 名区分；多到乱了再加分组，IM 有成熟解法。

和常见的多 agent 产品不同：它们的 team 是预先定义好的编排图，这里是**当场拉的群**，成员随时加减。协作靠群里的对话本身，bot 看得见彼此说了什么，不需要先画拓扑。

群里每个 bot 是**各自独立的后端会话，不共享 context**。群聊记录是它们共同订阅的外部事实，各自读进自己的历史。所以这不是「一个 agent 扮演多个角色」，是「N 个 agent 订阅同一条消息流」—— 代价是 N 倍 context 成本。

### 工作目录

**单聊 = 纯聊天，群 = 干活。** 一个 bot 加聊天空间是单聊；选了仓库，或者多个 bot，就是群。判定在 core 建会话时定，`shape` 只是呈现提示；**后端投递格式按成员数定**：只有一个成员时原样转发、harness 的 `/` 命令可用，加第二个成员才包成群聊记录。所以双人群在后端和单聊一模一样，差别只在界面：群标、成员面板、卡片上的 repo 名。

**聊天空间。** 单聊永远在自己的聊天空间里：`~/.roster/chats/<会话 id>/`，每会话一个，core 建会话时先建目录再插行。不涉及代码的讨论群也可以选它。删会话时一起删，归档保留，群换到仓库后也保留。界面上显示「聊天空间」而不是路径；桌面端能在 Finder 里打开。附件照旧放数据目录，不进工作目录。

**位置是建群的必填项**，三种来源：聊天空间（首次默认）、最近用过（core 从已有仓库会话取，去重、按最近、只列还在的）、其他目录（手填；桌面端有原生选择器，走 preload 暴露的两个 IPC，浏览器模式没有）。上次的选择记在窗口里。core 不再用自己的 `process.cwd()` 当默认目录——桌面壳启动 core 时它是 `packages/desktop`，打包后是 `/`，两个都不是任何人想要的。选的目录已经有会话在用只提示不阻止：写锁按会话，真正的隔离是每会话一个 git worktree，`worktree_path` 就是给它留的，现在等于 `repo_path`。

**换目录 = 全员重开后端会话。** 三种 harness 的恢复令牌都绑目录（Claude Code 的 session 存在 `~/.claude/projects/<cwd>/`，ACP 的 `loadSession` 要 cwd，pi 的令牌是按 cwd 建的 session 文件），所以改目录和令牌、投递进度的清零在同一个事务里；成员按「新成员」重新拿到带名单的完整记录，落一条系统通知。有成员在跑或正在启动时拒绝；单聊没有目录可改。

**chat 模式的 session。** 一个 session 就是一条单聊会话，自己的后端会话和聊天空间；同一个 bot 的几条在消息列表里收成一行：在等你的那条排位、带数量的徽标，点开进在等你的那条，否则上次看的。标题栏的切换器列出各条和状态，顶部「新会话」。不在一条线程里分段——事件流、投递进度、附件、排序都按会话建模，切回旧段时 bot 的上下文和记录会对不上。

### 模式 = 发言权的分配规则

群有模式，建群时选、随时能改。模式回答的其实只有一个问题：**谁是下一个发言的。**

| 模式 | 谁决定下一个发言 | 用在什么时候 |
|---|---|---|
| **人主导**（默认） | 人 @ 谁，谁接 | 大部分情况 |
| **群主分发** | 指定一个 bot 当群主，人只跟群主说，它拆解派活 | 任务能拆 |
| **讨论** | 所有成员都对同一条消息发表意见，人做裁决 | 方案评审、找 bug |

**说话可以并发，动手必须串行。** 冲突来自 worktree，不来自消息 —— 讨论阶段 bot 只读不写，可以一起说；要动手时排队，一次一个。

讨论模式的终止条件：**一轮 = 每个成员各说一次，然后停下等人。** 不设轮数上限 —— 轮数是个魔法数字，停在第几轮也是随机的；回到人则是确定的。

### 实现约定（第一版）

**投递。** 每个成员记着自己读到哪（`delivered_seq`）。轮到它时，把之后的广播事件 —— 人说的话、其他 bot 的最终回复、加入 / 离开 / 改模式这类系统通知 —— 拼成一段带成员名单的群聊记录交给它，末尾一句说明这次为什么轮到它。单聊里只有人说的话时原样转发，不包装。

**不 @ 时谁接话。** 人主导：上一个回复的成员，没有就第一个成员；群主分发：群主；讨论：所有人。`@所有人` 就是所有人。输入框在发送**之前**就写明这条会发给谁 —— 路由规则再简单，事后才知道发给了谁也是意外。

**群主分发的循环。** 群主回复里 @ 到的成员被派活；被派的都交回后群主再收到一轮，汇总或继续派；群主不再 @ 任何人就回到人。每条人的消息之后最多自动接力 24 次，超过就停下发系统通知。这不是轮数上限，是刹车：正常情况下循环由群主自己结束，刹车只防群主永远不停 —— N 个 bot 各自持有 context，没有刹车就没有花费上限。

**讨论只读。** 讨论模式下写和执行一律走权限卡片，由人决定，不是直接拒绝。

**快照与实时。** 预设、模型、后端是加入时的快照 —— 后端会话是用旧预设启动的，悄悄换掉等于改了一个正在跑的会话。改过之后成员面板提示「设定有更新」，同步 = 新开一个后端会话，并把群聊记录重新交给它。**权限档例外，读实时值**：降档必须立刻生效；会话里另选过一档的，按它自己选的来。

**写锁**按成员持有到本轮结束，同一个成员一轮里多次写不会自己锁住自己。

**晚加入的成员**拿到之前的群聊记录。超出预算时丢较早的 bot 发言和通知，**人说的话永远不丢**。

**名字**在通讯录里唯一，不能有空格和 @：`@名字` 必须只指向一个 bot。

**头像**只从一套 IP 形象里选（[ip-as-logo](https://github.com/s1dashu/ip-as-logo-skill) 仓库现成的 35 个），不支持 emoji 或自定颜色 —— 通讯录读起来得是一家人。新建 bot 默认分配还没人用的那个；单聊显示成员的头像，群聊把成员的头像斜向叠放，一张压一张（这套形象切成格子就认不出了，所以不拼格），最多叠三张，再多的在角上记个数；群也可以从同一套形象里选一个当头像，不选就是叠放。

**预设是追加，不是替换。** 两个后端自带的编码提示词是它们会用工具的原因，bot 的预设接在后面（Claude 用 `claude_code` preset 的 `append`，pi 用 `appendSystemPromptOverride`）。

## 三列布局

参照飞书：**导航栏 + 列表 + 详情**。

**一、导航栏**（最左，窄）—— 图标加文字的垂直入口：消息、通讯录。是常驻的一级导航，不是 tab bar——只有手机上才是（见 [移动端](mobile.md)）。

**二、列表**（中）—— 会话卡片：头像、名称、**身份标签**（哪个 bot、是不是 team）、**repo 名**、时间、最后一条消息摘要单行截断。
只有一种未读：**「在等你」**。运行中不标未读，只给一个弱的进行指示；跑完了才标。

**但「在等你」分两种，已读的处理不一样：**

| | 例子 | 打开会话后 |
|---|---|---|
| **通知** —— 你还没看 | 等你回复、出错了 | **清掉**，你看过了 |
| **活着的条件** —— 还没解决 | 等你批准、卡住了 | **不清**，看一眼不会让待批的操作消失 |

会话标题从**第一条消息**推导（剥掉 markdown、按句号断），不花模型调用；双击标题可改。默认标题「与 X 的会话」不携带任何信息。

**三、详情**（右）—— 顶部标题栏（头像、名称、身份标签），中间消息流，底部输入框。

### 消息用卡片

飞书把通知做成带标题栏的卡片，正文、元信息、操作按钮各归其位。这个形式直接拿来用：

- **工具调用**折叠成一张卡片（「执行了 N 步」，可展开）—— 不折叠的话，消息流会被读文件、跑命令刷满，人找不到真正要读的那几句
- **plan、diff** 同理
- **权限请求**一张卡片、两个按钮 —— **不是 modal**。modal 会阻塞，五个会话同时跑就是五个弹窗叠在一起；卡片能等，而且它是「在等你」未读最主要的来源

**权限是 bot 的属性。** 通讯录的资料页上有一个档位（只读 / 可写 / 可执行），超出档位才问 —— 只读的 review bot 永远不打扰你。全问会烦死，全放行不安全，档位是中间那条路。

**会话里可以另选一档。** 没有自己权限模式的后端（pi-agent），档位就是它会话的权限模式，在输入框下方和模型一起切换：只管这一个会话，从下一次工具调用起生效，不用重开后端会话；已经在等你的卡片照旧由你决定。没另选过的会话跟着 bot 的档位走；另选过的按自己选的，改 bot 不影响，同步也留着。讨论模式照旧只读。

**有自己权限模式的后端例外。** Claude bot 按会话的权限模式审批，名字和行为跟 Claude Code 一致（Manual / Accept edits / Plan / Auto / Bypass Permissions），在输入框下方和模型、思考级别一起切换；档位只决定新会话从哪个模式开始。模式要问人时仍然发权限卡片，讨论模式仍然强制问人，写锁照旧。

**后端的名字照抄，其余是 Roster 自己的。** 模式、模型、思考级别、套餐这些名字是后端的词，抄它的写法才不会对不上；上下文占用是每个后端都有的东西，所以面板是 Roster 自己的一套中文版式，右侧抽屉打开，只认协议里的 `parts` 和 `sections` —— 换成 pi-agent 的自定义模型，同一个面板照样用。

群聊里 bot 有头像和名字，像真人群聊。`@` 指定谁回复。点任何地方的 bot 头像（消息流、成员面板、在线条、单聊标题栏）弹出它的信息卡片：职责、agent 和模型、权限档、正在做什么，下面「发消息」「@ 它」（群里才有）「查看资料」——和 IM 里点人头像一个意思，不用跑去通讯录。加入、完成这类系统消息走居中细灰条，不进正常消息流。

### 输入框

**附件跟着消息走，不进仓库。** 文件存在 `~/.roster/attachments/<会话>/`，消息只记引用。交给 bot 时正文里写明每个附件和它的路径：短文本文件直接贴进去，图片在后端收图时再作为图片块原样附上 —— agent 自己去读仓库外的路径会弹权限询问，这两种都不用读。

**`/` 分两类。** Roster 自己的操作（压缩、切模型、看上下文、重命名）和后端自己的命令（名字和说明照抄后端，重名时让给 Roster）。后端命令只在单聊出现：群聊把消息包进群聊记录，开头的 `/` 到不了后端。

**第一版先保证布局和结构正确；视觉打磨从设置页开始**（见 [底层执行器 · 设置页的样子](harness.md#设置页的样子)）。shadcn 的默认长相跟飞书那种浅色圆角、大留白差得远，但那是 token 层的事，改的时候结构不用动。

## 底层执行器

session 背后真正干活的是现成的 code agent —— Codex、Claude Code、pi-agent 等。**不自写 agent loop**：模型升级、prompt 调优、context 管理都是它们在做，我们白拿这份红利。

差异化在上层，跟底层是谁无关：IM 形态、bot=联系人、群=team。

**agent 是 bot 的一个属性。** 通讯录里可以并存基于不同 harness 的 bot，一个群里也能混编。

harness、agent 和模型来源怎么分层、适配器怎么装、设置页长什么样、两个后端的控制面和事件模型，见 [底层执行器](harness.md)。

## 界面语言

先做英文和简体中文，结构上留给更多语言。

**语言由 core 保管，不由窗口保管。** core 自己也在写字：群里的提示、报错、交给 agent 的说明、默认的会话名、logo 的名字。所以选择存在 core 的 `preferences` 表里，窗口只缓存一份，好在 core 回话前就用对的语言画出来。「跟随系统」按 Electron 传来的 `app.getPreferredSystemLanguages()` 定（从 Dock 启动的进程读不到 `LANG`），没有再看 `LC_ALL`、`LANG`，都对不上就用英文；繁体中文不会落到简体上。切换立即生效：core 广播 `preferences`，窗口重新取状态和打开的会话，适配器按新语言重建；已经开着的后端会话，下次启动时才换语言。

**不引入 i18n 库。** core 和界面各一份词表（`packages/core/src/i18n`、`packages/ui/src/i18n`），和其它「两边各一份」的代码一样手动保持同步。key 是点号分隔的扁平字符串，参数写成 `{name}`，复数交给 `Intl.PluralRules`（中文不分单复数）。英文词表是基准，别的语言用 `translation<typeof en>()` 对齐：少 key、多 key、用了英文里没有的参数，都编译不过；调用时参数不对也一样。适配器各带一张小词表，按 `InstanceConfig.locale` 取。

**存下来的字分两种。** 群里的提示存 key 和参数，读的时候按当前语言重写，bot 补看历史时看到的也是当前语言；老数据里没有 key 的提示照原文显示。报错卡片、会话列表的预览、bot 的回复和人起的名字，按写入时的语言保留。默认会话名（「与 Pi 的会话」「新群聊」）按当前语言显示，第一条消息照旧替换它，两种语言写下的默认名都认得。

**不翻译的词。** harness 自己的词照它原样：Claude Code 权限模式和思考级别的名字、套餐用量、fast mode 用不了的原因，都和它自己的界面一致；模式下面那行说明是 Roster 写的，跟着翻译。`@所有人` 和 `@all` 在两种语言下都能用。

**加一种语言**：core 和界面各加一个词表文件并登记到 `LOCALES`，适配器的词表各补一份，Electron 的右键菜单和通知在 `packages/desktop/main.cjs` 里另有几句。

## 技术选型

**Electron，不是 Tauri。** 理由只有一条：**后端逻辑必然跑在 Node 上** —— Claude Code 的 SDK 在 Node 生态里。Tauri 的后端是 Rust，接这些就得 spawn 一个 Node sidecar，等于同时维护两套运行时，体积优势也被打包进去的 Node 抵消掉大半。Tauri 适合后端本来就能用 Rust 写的应用，这个不是。

**壳和核心分开。** 核心是独立的 Node 进程，不依赖任何 Electron API，能单独跑、也能用浏览器访问；Electron 只提供桌面能力 —— 系统通知、dock 未读角标、全局快捷键。这几样正是「列表按需不需要人排序」那条的载体，浏览器做不好。分开的另一半红利在[移动端](mobile.md)兑现：手机就是 core 的第二个客户端，连同一个 core、订阅同一条流。

| | 选择 | 注意 |
|---|---|---|
| 壳 | Electron | 只做桌面能力，不放业务逻辑 |
| 核心 | Node 独立进程，headless | 界面是它的纯投影，没有权威 |
| 界面 | React + **shadcn/ui** | 底座用 shadcn，在它之上打磨，不从零写组件 |
| 长列表 | 虚拟化 | 上千条消息不虚拟化会卡死；流式渲染要防重渲染风暴 |
| diff | CodeMirror 或 Monaco，**不自己写** | 关键是能往行间和边栏塞自定义元素 |
| 存储 | SQLite | 事件追加写，索引查询 |
| 手机 | 同一套界面的窄屏形态，原生壳（WKWebView）包起来上架 | 不写第二套界面；只在 iPhone 上验；直连免费，官方中继和推送随订阅（见 [移动端](mobile.md)） |

## 移动端

手机连回自己电脑上的 core，操作的是电脑上的 agent 和会话；它是同一套界面的窄屏形态，官方 app 是一层原生壳。直连免费，官方中继和推送是付费订阅、中继可自建。连通、配对、推送、账号见 [移动端](mobile.md)。

## 核心设计

**一、会话是持久对象，不是一次性对话。** 关掉再打开，上下文还在。

**二、列表按「需不需要人」排序，不按时间。** 等输入的排最前；运行中的沉底、不标未读 —— agent 自己能推进的时候不该占用你。这条决定整个界面的性格。

**三、worktree 归会话所有，群成员共享。** 会话之间互不干扰；群里的 bot 协作的是同一份代码，所以**动手要排队** —— 说话可以并发，写 worktree 一次一个。
