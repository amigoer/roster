# 移动端

> 第二轮 · 2026-09-17

**手机是 core 的第二个客户端，不是第二个 Roster。** agent 程序、仓库、worktree、密钥、登录全在桌面机上，手机上一样都跑不了——Claude Code 的 CLI 不跑在 iOS 上，仓库也不在手机里。所以手机端只做一件事：**离开桌面的时候看得到、答得上。** 壳和核心当初分开、core 只讲 HTTP + SSE、界面是纯投影，这笔红利现在兑现：手机连的是同一个 core，订阅的是同一条流，桌面和手机只是两个订阅者。手机上批准了一条命令，桌面上那张卡片同一秒变成已批准，两边没有任何同步代码。

## 手机上干什么

按「在等你」的几种情况来定，它们正是人不在电脑前时最需要手机的时刻：

- **批准** —— 权限卡片推到手机上，看清是什么命令再点允许或拒绝。这是手机端存在的第一理由
- **回复** —— bot 问了问题，或者跑完了在等下一步，手机上接着说
- **发起** —— 路上想到一件事，挑个 bot 开一个会话，回到电脑前已经干完了
- **看进展** —— 谁在跑、跑到哪、上下文用了多少

能做的和桌面一样多：发消息带附件（手机的强项是拍照，截图 bug 现场直接发，`<input capture>` 就够，不需要原生壳）、@、切模式和模型、加减成员、归档、中止、审批——因为走的是同一套 API。**不做的只有属于「那台机器」的事**：装 harness、填密钥、建 agent、选任意目录（没有原生选择器，只给聊天空间、最近用过和手填路径）、在 Finder 里打开。这些在手机上不出现，而不是灰掉。手机的设置页只有外观、语言和「这台手机」（解除配对）。

## 同一套界面，窄屏形态

**不写第二套界面。** 消息流、卡片、@、权限卡、markdown、虚拟列表是界面的大头，已经有一份；投影不值得第二份代码。手机端是同一个 React 包在窄屏下的另一种布局：

| 桌面 | 手机 |
|---|---|
| 导航栏，常驻竖排 | 底部 tab bar：消息、通讯录、我 |
| 列表和详情并排 | 两屏：列表 → 会话，推入推出，和所有 IM 一样 |
| 成员面板、上下文面板是右侧抽屉 | 底部 sheet |
| 输入框下方的模型 / 模式 / 思考级别一行 | 收进一个 sheet，输入框只留附件、@、发送 |
| 权限卡片两个按钮 | 同样两个按钮，做大、放在拇指够得着的地方 |

**断点按宽度定，不按设备定**：桌面窗口拖窄了也变成两屏，iPad 横过来就是三列。这样窄屏布局在桌面上就能做、就能验，不用先有手机。

**界面得认 URL。** 现在选中的会话只在 React 状态里，通知点开、刷新、从主屏 app 冷启动都落不到那条会话。加一层最薄的路由：`/c/<会话 id>`、`/contacts`、`/me`，桌面照样能用，浏览器的后退在手机上就是返回列表。

**「在等你」的排序不变，而且是所有端共享的。** 在手机上读了，桌面的角标也清——已读是会话的状态，不是设备的状态，多端 IM 一直就是这样。

## 先做主屏 web app，不做原生 app

桌面选 Electron 的理由（后端必然跑在 Node 上）在手机上不存在——手机上什么后端都不跑，只剩一个界面，那就让浏览器跑它。core 本来就把界面当静态文件发出去，手机打开同一个地址、「添加到主屏幕」，就有了图标、全屏、角标和推送。

| | 主屏 web app（PWA） | 原生壳（Capacitor 一类） | 单写一个原生 app |
|---|---|---|---|
| 界面 | 同一份 | 同一份 | 第二份，几十个组件重写 |
| 推送 | Web Push，core 直接发，不要服务器 | 走 APNs / FCM，要一台中继 | 同左 |
| 证书 | 只认系统信任的 | 能钉自签证书 | 能钉 |
| 分发 | 一个地址 | 上架或 TestFlight | 上架 |

原生壳能多买到的三样东西——钉自签证书、更稳的推送、上架——第一版一样都不需要；到需要那天，壳包的仍然是这一套界面，前面的活一点不浪费。

## 怎么连上

**core 不管网络怎么通，只管在哪个地址上听、认不认得来的人。** 桌面机在 NAT 后面、手机在 4G 上，打洞和中继是整个行业做烂了的事，不该由一个 code agent 客户端再做一遍。Roster 需要的只是「手机能打到的一个地址」，它怎么有的分三种，前两种第一版就认：

| 通路 | 怎么来 | 能做什么 |
|---|---|---|
| **tailnet**（Tailscale 一类） | 本机检测到 `tailscale` 就一键 `tailscale serve`：反代到 core 的远程端口，自带合法证书和 `*.ts.net` 域名；手机上装 Tailscale、登同一个账号，走到哪都通 | 全部，含推送 |
| **同一 Wi-Fi** | core 在局域网地址上听，配对码带上这个地址 | 只在家里通。明文 HTTP，浏览器不给它 service worker，所以没有推送、没有后台，只能开着看 |
| **自己的域名 / 反代 / 隧道** | 人填一个地址 | 全部；Roster 不检测、不代劳 |

为什么第一条是 Tailscale：它是「先看本机有什么」的延续——开发者机器上多半已经装了；证书和域名它白送（要在 Tailscale 后台开过 HTTPS）；线路是 WireGuard，令牌不裸奔。局域网通路只在自己的网络上开，咖啡馆的 Wi-Fi 该走 tailnet。公网暴露第一版不推荐：令牌挡得住人，挡不住扫描，要走公网自己在前面加反代和鉴权。

**两个端口，两条规矩。** 回环端口一个字不改：给桌面壳，本机不鉴权。远程端口只在打开「允许手机连接」时才开，默认关；**上面的每个请求都要设备令牌，不看来源地址**——tailscale 的反代也是从回环打过来的，按地址信任就等于把整个 tailnet 都放进来。

## 配对与鉴权

**配对 = 扫码，或者抄一个 6 位码。** 桌面设置页新增「手机」：一个开关「允许手机连接」，打开后显示二维码和一个 6 位配对码，10 分钟有效，输错五次作废。二维码只是把地址和码一起编进去省得打字；地址可能有几个（tailnet 域名、局域网 IP），手机挨个试，记住通的那个。兑换成功，core 给这台手机发一个**设备令牌**，从此每个请求带着它。令牌存 `devices` 表，只存哈希；桌面上列出已配对的手机（名字、上次在线），一键解除。

**令牌放 cookie，不放请求头。** 界面用的 `EventSource` 带不了头，cookie 它自动带，界面一行不用改；HttpOnly，HTTPS 上加 Secure，SameSite=Lax，别的网站发不出带 cookie 的请求。iOS 的主屏 app 和 Safari 不共享存储，所以 Safari 里只负责「添加到主屏幕」，配对在主屏 app 里输 6 位码完成；Android 共享，扫一次就完。

**配对的手机 = 本人。** 它能调的 API 和桌面一样，不做第二套权限模型——手机上不出现的功能是因为不合适，不是因为不允许。

## 推送

**推送不建服务器：Web Push 由浏览器厂商的推送服务送，core 自己发。** 主屏 app 向系统申请一个推送地址（Apple 或 Google 的服务器），交给 core；core 用自己生成的 VAPID 密钥，把加密过的内容直接 POST 过去。没有 Roster 的服务器、没有账号、没有 APNs 证书；内容端到端加密，推送服务只看得到一个信封。iOS 16.4 起主屏 web app 就能收，Android 一直能收。推送地址存在设备那一行，解除配对时一起删。

**推什么：一条会话进入「在等你」时推一次。** 内容是会话名加为什么等你——「登录 bug · 等你批准：`git push origin main`」——因为手机上的决定往往就是看一眼通知；已经在等的不重复推，读了或解决了就清。点开落在那条会话（就是上面要加的 URL）。角标用 Badging API，数字和桌面 Dock 上的一样。**「新进入在等你」的判定挪进 core**：现在桌面壳自己订阅流、自己数，手机推送也要同一个判定，两边各算一遍迟早对不上。

**通知上不放「允许」按钮。** iOS 的 web 推送目前就没有按钮；就算有，锁屏上一键放行一条命令也不是好主意——权限卡片的意义就是让人看清再点。通知只负责把人带到那张卡片。

## 桌面机得开着

**手机能用的前提是 core 在跑。** 今天 core 由桌面壳拉起、关窗即退。打开「允许手机连接」后改成**关窗不退出**：窗口关了 core 继续跑，菜单栏留一个图标（macOS 的常规做法），明确点「退出」才停。合盖睡眠会断线，第一版不解决，只在「手机」页提醒接电源、设置不睡眠。以后可以把 core 装成登录时启动的后台服务，壳只是连上去。

## 顺序

1. 窄屏布局和 URL 路由——桌面窗口拖窄就能验，不需要手机
2. 远程端口、`devices` 表、配对页、设置页的「手机」
3. tailscale 检测与一键 serve；局域网地址
4. Web Push 与角标；「在等你」判定进 core，桌面通知改用它
5. 关窗不退出、菜单栏图标

一二做完就能在同一 Wi-Fi 下用；三四做完才是「离开桌面也能批准」，那是这一轮的目标。

## 第一版不做

自建中继与打洞、原生 app、公网暴露、多用户与账号、手机上改 harness / 密钥 / agent、离线草稿、语音输入、通知上直接批准。

## 待定

**局域网通路要不要 TLS** —— 自签证书在手机上是一页警告，装 CA 是两步手工，而且警告页照样没有 service worker。第一版明文、只在自己的网络上开；真要在局域网上收推送，再做「安装证书描述文件」那一步。

**手机键盘上的 @ 输入** —— contenteditable 和输入法在 iOS 上历来多坑。不行就退回纯文本框加一个 @ 按钮弹选人，路由规则不变。

**主屏 app 被系统杀掉后的补课** —— 回到前台时 SSE 重连、整体重取，桌面上这条路已经在走；手机上一天要断几十次，重取的量和速度要真机验过才知道够不够。
