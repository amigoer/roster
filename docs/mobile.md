# 移动端

> 第二轮 · 2026-09-17

**手机是 core 的第二个客户端，不是第二个 Roster。** 场景只有一个：电脑在家开着 Roster，人在外面，手机连回家里的 core，看的、批的、发的都是电脑上的 agent 和会话。agent 程序、仓库、worktree、密钥、登录全在桌面机上，手机上一样都跑不了——Claude Code 的 CLI 不跑在 iOS 上，仓库也不在手机里。所以手机端只做一件事：**离开桌面的时候看得到、答得上。** 壳和核心当初分开、core 只讲 HTTP + SSE、界面是纯投影，这笔红利现在兑现：手机连的是同一个 core，订阅的是同一条流，桌面和手机只是两个订阅者。手机上批准了一条命令，桌面上那张卡片同一秒变成已批准，两边没有任何同步代码。

**卖的是「连得上、叫得醒」，不是 app。** 本体开源免费，手机 app 免费下载。官方中继让手机和家里的电脑扫码即通，不装 Tailscale、不开端口；推送让你不用开着 app 也知道有会话在等你。这两样是付费订阅。**免费这条路是完整的产品，不是试用版**：直连、自建中继、app 都免费，自建的方案正式支持、有文档、和官方跑同一个程序；付钱买的只是「不想自己搭」和推送。推送只有官方能发——APNs 的密钥只有一把。见「中继」和「账号与订阅」。

## 手机上干什么

按「在等你」的几种情况来定，它们正是人不在电脑前时最需要手机的时刻：

- **批准** —— 权限卡片推到手机上，看清是什么命令再点允许或拒绝。这是手机端存在的第一理由
- **回复** —— bot 问了问题，或者跑完了在等下一步，手机上接着说
- **发起** —— 路上想到一件事，挑个 bot 开一个会话，回到电脑前已经干完了
- **看进展** —— 谁在跑、跑到哪、上下文用了多少

能做的和桌面一样多：发消息带附件（手机的强项是拍照，截图 bug 现场直接发，`<input capture>` 就够，不需要原生壳）、@、切模式和模型、加减成员、归档、中止、审批——因为走的是同一套 API。**不做的只有属于「那台机器」的事**：装 harness、填密钥、建 agent、选任意目录（没有原生选择器，只给聊天空间、最近用过和手填路径）、在 Finder 里打开。这些在手机上不出现，而不是灰掉。手机的设置页只有外观、语言和「这台手机」（解除配对）。

## 同一套界面，窄屏形态

**不写第二套界面。** 消息流、卡片、@、权限卡、markdown、虚拟列表是界面的大头，已经有一份；投影不值得第二份代码。手机端是同一个 React 包在窄屏下的另一种布局：

| 桌面 | 手机 |
|---|---|
| 导航栏，常驻竖排 | 底部 tab bar：消息、通讯录、我 |
| 列表和详情并排 | 两屏：列表 → 会话，推入推出，和所有 IM 一样 |
| 成员面板、上下文面板是右侧抽屉 | 底部 sheet |
| 输入框下方的模型 / 模式 / 思考级别一行 | 收进一个 sheet，输入框只留附件、@、发送 |
| 权限卡片两个按钮 | 同样两个按钮，做大、放在拇指够得着的地方 |

**断点按宽度定，不按设备定**：桌面窗口拖窄了也变成两屏，iPad 横过来就是三列。这样窄屏布局在桌面上就能做、就能验，不用先有手机。

**界面得认 URL。** 现在选中的会话只在 React 状态里，通知点开、刷新、从 app 冷启动都落不到那条会话。加一层最薄的路由：`/c/<会话 id>`、`/contacts`、`/me`，桌面照样能用，浏览器的后退在手机上就是返回列表。

**「在等你」的排序不变，而且是所有端共享的。** 在手机上读了，桌面的角标也清——已读是会话的状态，不是设备的状态，多端 IM 一直就是这样。

## 官方 app：原生壳包同一套界面

桌面选 Electron 的理由（后端必然跑在 Node 上）在手机上不存在——手机上什么后端都不跑，只剩一个界面。但要上架、要走 IAP 收订阅、要收 APNs 推送，就得有一个 app。三条路：

| | 主屏 web app（PWA） | 原生壳（WKWebView）包同一套界面 | 纯原生重写 |
|---|---|---|---|
| 界面 | 同一份 | 同一份 | 第二份，几十个组件重写 |
| 推送 | Web Push，core 直接发 | APNs，经官方服务器 | 同左 |
| 订阅 | 只能在网页上卖 | IAP | IAP |
| 分发 | 一个地址，「添加到主屏幕」藏得深 | App Store | App Store |
| 审核风险 | 无 | 「网页套壳」可能被 4.2 拒，靠原生的配对、推送、钥匙串、订阅撑 | 无 |

**选原生壳。** 界面还是那一份；原生只做界面做不了的：扫码、钥匙串、APNs、通知扩展里解密、IAP。界面从哪来和桌面一样——core 发什么，壳就显示什么，所以界面永远和 core 同版本，改界面不用发新 app；壳缓存一份，打开先有画面再连；配对、账号这些没有 core 也要能打开的页面，打在壳自带的引导包里，也是 web。Web Push 技术上能免费做，我们不做：推送是订阅的一部分，这是生意的决定，不是技术的。审核要备一台演示用的电脑挂在官方中继上。

**壳用各自的原生语言写：iOS 是 Swift，Android 是 Kotlin，不用跨端框架。** 壳里没有界面可共享——界面是那份 web 包——剩下的每一件都是平台自己的 API：扫码、Keychain / Keystore、APNs / FCM、StoreKit / Play Billing。壳没有自己的页面，只弹系统的：扫码器、Sign in with Apple / Google、购买。跨端框架解决的是「共享界面代码」，这里没有这个问题，引进来只多一层运行时和一堆插件，通知扩展照样得写 Swift。每个壳几千行，写两遍比养一个框架便宜。

**手机侧的垫片在 web 层，不在壳里。** 界面所有请求本来就走 `api.ts` 一个口子，把 `fetch` 和 `EventSource` 换成经中继的加密 WebSocket 是 JS 的事，两个平台共用；壳只把钥匙串里的秘密递给它，另带一个小引导页，先把隧道接上再从 core 取界面。推送解密两边不同：iOS 在通知扩展里解，Android 在 FCM 数据消息的回调里解、自己发本地通知。

**两个端的界面因此是同一份，差别只剩系统强加的三件小事**，在 web 层按平台各处理一句：安全区（刘海、Home 条），Android 的返回键接到路由上，键盘弹起时输入框的位置。

## 先只管 iPhone

**验收只在 iPhone 上做。** 一个人做，两台真机就是两倍的坑。「不跨端」花在壳上，不花在界面上——界面本来就是一份；Android 之后是一层 Kotlin 壳加 FCM，走同一个中继，不是现在的事。

**iOS 的几条硬约束，设计已经按它来了：** 推送内容在通知扩展里解密；app 退到后台就断流，回来重连、整体重取；拍照用 `<input capture>`，壳不用再做相机（配对扫码除外）；密钥进钥匙串，不进 WebView 的存储。

## 怎么连上

**core 不管网络怎么通，只管认不认得来的人。** 两道门，都由「设备」守着：

| 通路 | 怎么来 | 谁用 |
|---|---|---|
| **直连** | core 开远程端口：同一 Wi-Fi；tailnet 或自己的域名走到哪都通 | 免费；开发和自测也走这条 |
| **中继** | core 主动连出去一条 WebSocket，手机连同一台中继，中继把两边接起来 | 官方中继随订阅；自建的免费 |

直连是老设计，一字不改：远程端口默认关，每个请求要设备 cookie，不看来源地址（tailscale 的反代也是从回环打过来的，按地址信任等于把整个 tailnet 放进来）。中继是新加的门：core 连出去，所以家里不用开端口、不用管 NAT，扫码即通——这就是订阅卖的东西。公网直接暴露 core 不推荐：令牌挡得住人，挡不住扫描；有中继就没有理由这么做。

## 中继

**中继只搬密文，不认识 Roster。** 它不知道什么是会话、什么是权限卡片，只知道「这台电脑和这部手机是一对」，把一边的帧原样交给另一边。两头各一个薄垫片：手机这边把界面发出的 HTTP 请求和要订阅的 SSE 装进加密帧，电脑这边解开、打到 core 自己的回环端口。所以 API 随便改，中继不用动；中继开源，协议就是「帧」，不是 Roster 的接口。

**端到端加密，密钥从不经过中继。** 配对二维码里有一个 32 字节的秘密，两边由它派生会话密钥，每一帧加密并认证。中继被攻破的后果是断服务，不是泄代码、不是伪造批准。它能看到的只有：哪个账号、哪台电脑、什么时候在线、帧多大。这一条必须是构造上成立的，不是隐私政策上承诺的——中继上过的是代码和 diff。

**自建 = 同一个程序，少一层。** `packages/relay` 是一个 Node 进程：一个 WebSocket 端口，TLS 由前面的反代管，配对表在内存或 SQLite。官方在它前面加账号、订阅校验、APNs 发送；这一层不开源，也没法自建——APNs 密钥只有一把。

**自建是正式支持的方案，交付四样东西**：Docker 镜像和 `npx` 两种启动方式，一条命令跑起来；一页自建指南（域名、反代、证书、升级）；和官方同一个版本号、同一套协议，官方能连的自建就能连；一个共享令牌写在中继和桌面的设置里，陌生人连不上你的中继。**中继地址在桌面上选，不在 app 里填**：设置页「手机」里三选一——官方、自己的地址、不用中继（只直连）；二维码把它带给手机。自建的能连通，收不到推送（见「待定」）。

## 配对与鉴权

**中继上只扫码，直连才有 6 位码。** 桌面设置页「手机」：开关、二维码、已配对列表和解除。二维码里是中继地址（或直连地址）、这台电脑的标识和 32 字节秘密；短码走中继会被中继猜，所以 6 位码只在直连、由 core 限次。兑换成功，core 记一台设备（`devices` 表，存哈希），手机把秘密存进钥匙串。

**账号只在手机上，桌面没有账号。** 手机用 Sign in with Apple 登录官方中继、在 app 里订阅；扫码时手机告诉中继「这台电脑是我的」，电脑拿二维码里的凭据连中继，中继认它是因为手机登记过。一个账号可以登记几台电脑、几部手机，都在手机的账号页里看得到。直连和自建中继没有账号这回事。

**直连的令牌放 cookie**：界面用的 `EventSource` 带不了头，cookie 它自动带，界面一行不用改；HttpOnly，HTTPS 上加 Secure，SameSite=Lax。中继上不需要 cookie，隧道本身就是身份。

**配对的手机 = 本人。** 能调的 API 和桌面一样，不做第二套权限模型——手机上不出现的功能是因为不合适，不是因为不允许。

## 推送

**推送经官方服务器发 APNs，内容端到端加密。** 「新进入在等你」的判定在 core；core 把标题和正文用和手机共享的密钥加密，交给官方服务器，服务器只把密文塞进 APNs 的信封；手机上的通知扩展解密后再显示，解不开就显示「有会话在等你」。服务器和 Apple 都只看到信封。推送地址（APNs token）登记在设备那一行，解除配对时一起删。

**推什么：一条会话进入「在等你」时推一次。** 内容是会话名加为什么等你——「登录 bug · 等你批准：`git push origin main`」——因为手机上的决定往往就是看一眼通知；已经在等的不重复推，读了或解决了就清。点开落在那条会话。角标数字和桌面 Dock 上的一样。**判定挪进 core**：现在桌面壳自己订阅流、自己数，手机推送要同一个判定，两边各算一遍迟早对不上。

**通知上不放「允许」按钮。** 锁屏上一键放行一条命令不是好主意——权限卡片的意义就是让人看清再点。通知只负责把人带到那张卡片。

**没有订阅就没有推送。** 直连和自建中继的用户打开 app 才看得到；「不用开着也知道」正是订阅买的东西。

## 账号与订阅

| | 直连 | 自建中继 | 官方订阅 |
|---|---|---|---|
| 连通 | 同一 Wi-Fi；tailnet 或自己的域名 | 自己的服务器，走到哪都通 | 扫码即通 |
| 推送 | 无 | 无 | 有 |
| 账号 | 无 | 无 | 手机上登录，桌面不需要 |
| 收费 | 免费 | 免费 | 订阅，走 IAP |

免费的两档是完整的产品，和订阅一样认真做，不然产品传不开：直连加 Tailscale、或者自己的一台中继，就是一个完整的「离家可用」，只是要自己搭、要打开 app 才看得到。订阅省的正是这两件事。定价和试用不在这里定。

## 桌面机得开着

**手机能用的前提是 core 在跑。** 今天 core 由桌面壳拉起、关窗即退。打开「允许手机连接」后改成**关窗不退出**：窗口关了 core 继续跑，菜单栏留一个图标（macOS 的常规做法），明确点「退出」才停。走中继时 core 是连出去的，家里不用开端口。合盖睡眠会断线，第一版不解决，只在「手机」页提醒接电源、设置不睡眠。以后可以把 core 装成登录时启动的后台服务，壳只是连上去。

见 [路线图](roadmap.md) 的 M1 到 M7：窄屏与路由、直连与配对、中继、官方 app、官方中继与订阅、推送、上架。前两步做完就能在同一 Wi-Fi 下用；到 M4 有了 app、有了自建中继就是完整的免费版；M5 到 M7 才是卖的东西。

## 第一版不做

打洞、纯原生界面重写、Web Push、公网直接暴露 core、Android、同一台电脑多个人用、手机上改 harness / 密钥 / agent、离线草稿、语音输入、通知上直接批准。

## 待定

**自建中继的用户要不要给推送** —— 成本几乎为零，但削掉订阅的一半理由。先不给，看有没有人真的要。要给的话做法是现成的：一个免费的推送网关，app 向它领一个推送 id、配对时交给 core，core 把密文发给网关，网关按 id 限额，不需要账号——Home Assistant 就是这么给自建用户发推送的。

**短码走中继** —— 真要做就得上 PAKE，中继才猜不到；第一版中继上只扫码。

**审核** —— 网页套壳被 4.2 拒的风险，靠原生的配对、推送、钥匙串、订阅撑；被拒了再补原生的会话列表。

**局域网通路要不要 TLS** —— 只关直连。自签证书在手机上是一页警告，装 CA 是两步手工。第一版明文、只在自己的网络上开。

**手机键盘上的 @ 输入** —— contenteditable 和输入法在 iOS 上历来多坑。不行就退回纯文本框加一个 @ 按钮弹选人，路由规则不变。

**app 被系统杀掉后的补课** —— 回到前台时重连、整体重取，桌面上这条路已经在走；手机上一天要断几十次，重取的量和速度要真机验过才知道够不够。
